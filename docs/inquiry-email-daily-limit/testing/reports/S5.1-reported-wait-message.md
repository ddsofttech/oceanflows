# S5.1 — Reported “Could not send right now / Please wait a moment”

- **Date (UTC):** 2026-11-27
- **Environment:** Production `https://oceanflows.net/` (#contact on home page)
- **Build:** RP1 @ merge `c950a6e5`

## Reported symptom

Contact inquiry form showed:

> Could not send right now  
> Please wait a moment and try again.

## Client → API mapping (`web/src/scripts/inquiry-form.ts`)

| Visible copy | `InquiryUiOutcome` | Typical API |
|---|---|---|
| **Please wait a moment and try again.** | `rate-limited` | HTTP **429** `{ "error": "rate_limited" }` |
| Try again, or email us at … | `delivery-failure` / `unknown-error` | HTTP **502** `{ "error": "delivery_failed" }`, fetch/network error |
| Daily inquiry limit reached … | `daily-limit-reached` | HTTP **429** `{ "error": "daily_limit_reached" }` |
| Could not send … (no “wait a moment”) | `rejected` | HTTP **200** `{ "sent": false, "rejected": true }` (Turnstile/spam) |

The reported strings match **`rate-limited` only** (lines 271–273 in `inquiry-form.ts`).

## Reproduction

**Reproduced:** **Yes** (API and live form UI).

### API (curl, same egress IP)

1. Burst after prior probes: `POST /api/inquiry` (valid body) → **429** `{"error":"rate_limited"}`.
2. Immediate second POST → **429** `rate_limited` on validation-only `{}` when window full.
3. After 62s cooldown, single valid POST → **502** `{"error":"delivery_failed"}` (separate finding; see `DEFECT-IEDL-PROD-502.md`).

### Browser (https://oceanflows.net/#contact)

Filled valid fields, submitted once after QA curl traffic on same IP → status region showed **“Please wait a moment and try again.”** (matches human report). Accessibility snapshot ref: status text `Please wait a moment and try again.`

Production HTML: `data-turnstile-site-key` **empty** (Turnstile widget not mounted); rules out Turnstile `rejected` copy for this path.

## Cause classification

| Hypothesis | Verdict |
|---|---|
| IP burst BR-13 (`rate_limited`) | **Confirmed** for reported copy |
| Daily cap (`daily_limit_reached`) | **Ruled out** (different UI headline) |
| Resend / delivery (`delivery_failed`) | **Ruled out** for reported copy (different subtitle) |
| Turnstile / spam `rejected` | **Ruled out** (no site key on page; different copy) |

## Likely user path

1. First POST from client IP within rolling 60s (including a failed **502** delivery attempt, which still consumes the IP slot per `submitInquiry` order in `web/src/pages/api/inquiry.ts`), **or** rapid double-submit / retry after an error.
2. Second POST within 60s → **429** `rate_limited` → exact reported message.

This is **expected RP1 behavior** (BR-13, 1 POST per IP per 60s), not a misconfiguration of the rate-limit message itself.

## Defect filed for reported symptom?

**No.** Working as designed for `rate_limited`. Related production **502** on first successful-path submit filed separately (`testing/defects/DEFECT-IEDL-PROD-502.md`).

## Recommended owner

- **Reported wait message:** No code change required; orchestrator may ask human whether they retried within ~60s.
